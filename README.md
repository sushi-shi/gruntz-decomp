## Requirements

Linux (x86_64) with [Nix](https://nixos.org/download) and flakes enabled
(`experimental-features = nix-command flakes`). The flake fetches `GRUNTZ.EXE`
and the MSVC 5.0 toolchain.

## Quickstart

```sh
nix develop          # one shell: MSVC 5.0 under Wine plus every analysis tool
gruntz init          # the build Wine prefix (also run on shell entry)
gruntz build         # compile and compare every unit
gruntz match fader   # the matching loop: one unit in a few seconds
gruntz build verify  # the MAX gate and gate tiers, before a merge
gruntz sema -h       # navigate the retail image (xref, disasm, rva, class, ...)
```

The report lands at `build/objdiff/compare-new/report.json`;
`gruntz verify status` prints the per-function scores. Read next:
[documentation index](docs/README.md), [build system](docs/build-system.md),
[tooling map](docs/tooling-map.md), and [AGENTS.md](AGENTS.md) for the rules.

## The pipeline

```
src/ labels + config/retail/  -> claims -> the Model (build/gen/bindings.tsv)
                              -> synthetic PDB -> vostok-delinker -> retail "target" objs
src/*.cpp                     -> MSVC 5.0 under Wine -> "base" objs
base vs target                -> objdiff report -> CUR, MAX and HIST per function
```

The delink half reruns only when labels change. `gruntz match <unit>` runs the
whole chain for one unit; `gruntz build` runs it for all; `gruntz build verify`
adds the gates.

## Repo layout

```
src/            reconstructed C++, grouped by retail compiland (Gruntz/, DDrawMgr/, ...)
include/        shared headers; rva.h holds the address annotations
vendor/         third-party source, kept verbatim (zlib, miles, smacker, sfman)
config/         units.toml (build manifest), match_baseline.tsv (scores), retail/ labels
scripts/gruntz/ the `gruntz` CLI and pipeline
docs/           usage and contracts; start at docs/README.md
tools/          Rust codecs for the game's resource formats
recomp/         harness that runs retail's own code as an oracle
AGENTS.md       the agent guide (CLAUDE.md links to it); skills in .agents/skills/
build/          all generated state (gitignored)
```

## Link status

Linking is opt-in: `gruntz link` produces `build/exe/GRUNTZ.candidate.EXE` and
its `.map`, and `gruntz verify check --tier link` audits it for unresolved
externals, the section table against retail's, and every 100% function's bytes
at its link-assigned address. See [`docs/image-diff.md`](docs/image-diff.md).

## Resources

`.rsrc` is compiled from source: `src/Gruntz/Gruntz.rc` plus
`src/Gruntz/res/` carries all 75 retail resources, and `gruntz rsrc check`
builds them with the era `RC.EXE` and byte-compares each one against retail.

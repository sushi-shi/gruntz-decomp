# Use surviving source as a complete, revision-aware hypothesis

Related source can expose a class, helper, template, local lifetime, or expression
boundary that hand-expanded reconstruction erased. Inspect the complete owner
and its uses rather than borrowing only equivalent arithmetic.

Adoption decisions, retained differences, and evidence belong in
[the lineage ledger](../../config/lithtech_lineage.tsv), not in this reference.
The [historical case collection](https://github.com/sushi-shi/gruntz-decomp/blob/b27b05deb249e4cacbb29f55f17b469ecfe56f26/docs/patterns/surviving-source-lineage-restores-typed-layers-and-order.md)
provides provenance; its outcomes are not universal compiler rules.

Check layout, widths, calling conventions, ownership, control flow, constants,
and ordered relocations against Gruntz retail. A score change alone neither
validates nor refutes the source family. An exact reconstruction likewise does
not establish that its inferred names or abstractions are original.

Paired Debug/Release library members can supplement missing source: CodeView
types, local names, and lexical blocks provide positive source-shape evidence;
Release code provides optimized topology. Debug stack offsets and register
choices are not predictions for the retail build. Missing records, unsupported
decoders, and revision differences limit negative conclusions.

Do not import incompatible layouts or later-compiler behavior. Check reuse terms
before copying external source; keeping an evidence link is not permission to
redistribute it.

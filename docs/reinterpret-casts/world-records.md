# WWD byte storage and record views

This family starts with eight spelled casts: six in `GameLevel.cpp` and two in `LevelPlane.cpp`. One artificial record-pointer detour has been removed; seven casts remain. The table accounts for every starting expression and its disposition. Record names describe reconstructed wire fields; they are not evidence that a C++ object of that type was constructed inside each input buffer.

## Allocation and ownership chain

[LoadFromFile](../../src/Gruntz/GameLevel.cpp#L236) allocates `new u8[file.GetLength()]`, reads the file, calls `LoadWwd`, then deletes the allocation. Its `RecordBytes<WwdHeader>` union supplies the initial record view. [LoadFromSource](../../src/Gruntz/GameLevel.cpp#L259) borrows `CRezItm::Load()` storage and calls `UnLoad()` after parsing. Both therefore retain the underlying bytes during the synchronous readers. The union and the alternative cast through `void*` do not independently prove object lifetime or alias safety.

For compressed input, [LoadWwd](../../src/Gruntz/GameLevel.cpp#L140) allocates a separate `Bytef[]`, copies/inflates into it, and frees it at the success/failure exits. Header metadata continues to be read from the original `source`; plane/table offsets use the decompressed `block`. W2 now expresses that returned byte storage directly. It does not claim a constructed decompressed `WwdHeader`, nor change the allocation, decompression call, null-result check, or cleanup owner.

[CLevelPlane::Read](../../src/DDrawMgr/LevelPlane.cpp#L121) copies the tile run into its own `new i32[]`. [ReadObjectRecord](../../src/DDrawMgr/LevelPlane.cpp#L565) constructs a sprite and local `CString` values from the input, then initializes owned object fields; it does not intentionally retain `recordCursor`. Plane/table views must not outlive the source or inflate buffer. The separately owned tile/object state is what survives parsing.

## Safety and open contracts

**W1, W2, W6: byte views.** `char` and `unsigned char` can access object representation; [Bytef is u8](../../include/Wwd/WwdFile.h#L15). These conversions themselves require no stronger alignment. However, a byte pointer derived from a `WwdHeader*` does not prove that bytes beyond that header exist. The file/Rez allocation, not `sizeof(WwdHeader)`, must provide that extent. No source-length parameter reaches `LoadWwd` or `InflateMainBlock`.

**W4 and W5: table overlays.** The [declarations](../../include/Wwd/WwdFile.h#L23) establish field layout in this reconstruction. They do not validate file offsets, table counts, or the alignment of addresses derived from input. The typed plane-pointer increment also assumes a correctly laid-out contiguous sequence. Allocator alignment at the buffer base does not ensure that an arbitrary file offset is aligned. Dereferencing a record pointer additionally needs an object-lifetime/representation justification; `reinterpret_cast` is not a constructor. MSVC 5/x86's observed wire loads do not constitute portable C++ proof.

**W7: tile integers.** The destination is a real integer array. The source is still serialized bytes, and direct `i32` loads depend on the target's little-endian representation and alignment behavior. Rows-times-columns multiplication, the allocation extent, and `m_tilesOffset + byteCount` are not checked against the input allocation. A plausible field type or matching size is not sufficient to establish those bounds.

**W8: variable object records.** The fixed prefix is followed by string lengths supplied by the record. Successive cursors advance by `0x11c` plus those lengths, with no alignment rounding. Thus even an aligned first record does not establish aligned later records. x86 can perform the corresponding unaligned loads, but that does not make arbitrary typed-pointer dereferences portable. [ReadPlaneString](../../src/DDrawMgr/LevelPlane.cpp#L554) also copies an unchecked positive length into a 0x400-byte local buffer and appends a terminator. The record-count loop carries no end pointer. These are concrete unchecked assumptions in current source, not protections supplied by the cast.

Further limits: `LoadWwd` copies its complete header after only an upper-bound header-size check, not a file-length check. W5 forms `rec->m_descriptors` before its null checks, which cannot validate an offset into the allocation. `InflateMainBlock` uses the header's main-block length as both the input length passed to zlib and the expected output length; available compressed input length is not supplied independently. Its size-test polarity and those arguments are explicitly described as retail behavior in the introducing reconstruction commit below. This audit did not re-disassemble every unchecked access; absent checks must not all be labeled either newly invented bugs or proven retail bugs by association.

## Independent code and possible repairs

[OpenClaw's WWD reader](https://github.com/pjasicek/OpenClaw/blob/5ee5740ca98377c76b13b50c84f610b0066a4717/libwap/WwdFile.cpp#L21-L38) locates tile data by offset and reads each tile into an allocated integer array. Its [object reader](https://github.com/pjasicek/OpenClaw/blob/5ee5740ca98377c76b13b50c84f610b0066a4717/libwap/WwdFile.cpp#L61-L138) reads scalar fields and trailing strings separately; its [plane reader](https://github.com/pjasicek/OpenClaw/blob/5ee5740ca98377c76b13b50c84f610b0066a4717/libwap/WwdFile.cpp#L140-L188) likewise populates live structures rather than overlaying the input. This is an independent related-format implementation, not original Gruntz source or proof of all Gruntz extensions.

Its [stream primitive](https://github.com/pjasicek/OpenClaw/blob/5ee5740ca98377c76b13b50c84f610b0066a4717/libwap/IO.h#L73-L85) obtains a character view of an existing destination object, copies bytes, and handles endianness. That illustrates the distinction between byte access to a live value and typed overlays on source storage. Its own bounds expression still requires scrutiny for unsigned underflow; this audit does not certify the external parser.

**Disposition:** remove the W2/W3 record detour, retain the remaining format boundaries pending stronger evidence. A bounded byte reader that copies fixed records/scalars into aligned live locals could address alignment and lifetime assumptions; it must also carry actual allocation lengths and validate variable strings/counts. Merely replacing these casts with `RecordBytes` union accesses or casts through `void*` would hide the same problems. Adding bounds checks, changing decompression lengths, or replacing the parser wholesale would require a separate source/retail behavior decision. No such behavior repair was made here, and no claim of binary equivalence for the small cleanup is made without the parent's combined verification.
